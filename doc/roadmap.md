## Phase 3 - Hardening

Tracked on GitHub: #14 (tracking issue) with sub-issues #3-#13 in priority tiers.

1. `--delete` safety (`--yes`, `--max-delete`, confirm prompt); today those
   flags are rejected as unknown at parse time and the help text carries the
   permanent-`--delete`-no-confirmation warning until this lands
2. Ignore patterns + Obsidian default profile (`[ignore].patterns` already
   parses but is unused, W25/M3; remaining work is walker application plus
   the profile)
3. Concurrency limits (bounded request/transfer pool)
   (**landed under #20** - `[transfer].concurrency` is live: transfer passes
   and list-enrichment heads run through a bounded `std::thread` work-pull
   pool (`crate::pool::run_bounded`), `concurrency = 1` stays byte-for-byte
   sequential on the caller thread, reports are assembled in plan order, and
   the W28/M6 inert warning is deleted; see I20-pool / I20-w48 below). The
   **retries-with-backoff half landed under #8** (I8-retry-sdk below): the
   SDK standard-mode `[transfer.retry]` `RetryConfig` owns retry/backoff/
   jitter for all ops, and the W117 head stopgap is retired. (The SDK's
   client-side retry quota is shared: parallel workers on the same sustained
   storm burn the same standard-mode token bucket faster, so the quota
   interaction stays a tuning note for large vaults.)
4. Lock file to prevent concurrent runs on same vault
5. JSON schema stability for `--json` (parses today; dispatch rejects with
   "not implemented (Phase 3)" + exit 1)
6. Integration test optional gate in CI (**done, issues #6 + #17** -
   `VAULTSYNC_TEST_S3_REQUIRE=1` no-silent-skip sentinel in the harness;
   single OIDC-authenticated `integration` job on push/PR/schedule against a
   dedicated test bucket under `ci/` with a 7-day lifecycle backstop;
   `timeout-minutes: 20` hang guard. The I6-trigger PR-gate vs nightly split
   and the `--skip s3_integ_list_paginates` flag retired with #17 -
   `s3_integ_list_paginates` runs on every PR at `with_store_conc(128)` with
   seed fan-out 64 + unenriched cleanup list + parallel deletes, ~18-24s live
   on `us-west-1` after the P30-paginate-sub-30s knob sweep)
7. CI: pin the toolchain and verify MSRV (**done, issue 5** - `rust-toolchain.toml` pins 1.95.0; `rust-version = "1.95"` verified against the final dep tree in CI by the `msrv` job; fmt/clippy/test on ubuntu+macos via rust-cache). The B-L7 remainder (bucket env var in CI + no-silent-skip hardening) landed under item 6 / issues #6+#17
8. Consider anchoring a relative `vault_root` to the config file's directory
   instead of the cwd (PR2 B-L10) - breaking-change review
9. Cloudflare R2 endpoint matrix row (still pending; the path-style toggle
   test exercises both flavors there, PR2 A-M8/W12)
10. Walker depth: recursion is unbounded; add a depth cap or iterative walk
    before executor-era deep trees (re-deferred from the Phase 2 checklist,
    L3)

Streaming note (landed, no Phase 3 work): `get_to` streams the body;
`put_from` buffers to a disk temp and streams it via `ByteStream::from_path` -
never a size-sized memory buffer; the 5 GiB single-PUT ceiling is rejected
client-side before buffering (W80). Multipart upload above the ceiling is
post-v1 (see the post-v1 table).

Exit criteria: daily-driver usable for single-user backup (`push --delete` from trusted machine).

## Explicitly later (post-v1)

| Item | Notes |
| ---- | ----- |
| Bidirectional `sync` command | Only as documented composition + policy |
| Local prev-sync history (v3-like) | Enables deletion propagation without full mirror |
| Encryption wrapper | AGE or rclone-compatible; separate layer |
| Azure Blob / GCS backends | Same `ObjectStore` trait |
| Obsidian community plugin | Thin: shell out or embed; no logic fork |
| Watch mode / launchd helper | Wrapper around CLI |
| Multipart upload above the 5 GiB single-PUT ceiling | Post-v1 per W80 + cli.md/object-store.md; support + tuning when large video/PDF users appear; until then oversized objects are rejected client-side before buffering |

| Conflict copies | `file.conflict.<ts>.md` optional policy |
| Trash-based local deletes | Optional safer local delete behind `--delete` |

## TDD protocol (applies to every work item)

1. **RED:** write the failing test(s) listed under the item first, in the stated file. Run `cargo test --offline <name>` and confirm the exact failure. Do not touch production code before the RED is observed.
2. **GREEN:** implement the smallest change that passes. Run the item's tests, then the full `cargo test --offline`.
3. **Refactor:** only with tests green; keep it inside the same item or call it out.
4. **Gate:** `cargo clippy --all-targets -- -D warnings` and `cargo fmt --check` clean.
5. **Commit:** one commit per work item, message `fix: <summary> (PR2 W<n>)` (or `docs:` / `test:` / `refactor:` / `chore:` per repo convention). Amendments to *existing* tests that locked the old behavior are allowed only where the item explicitly says so, and ride in the same commit.
6. Work lands on `phase-2-real-fs-s3` in the order below; each commit leaves the tree green.

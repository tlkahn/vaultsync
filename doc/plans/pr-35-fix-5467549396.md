## Implementation discipline

**Strict fine-grained TDD** on every behavior-facing change:

1. **RED** - write or extend the exposing test first; run it; observe the
   expected assertion failure (or compile failure) *before* touching production
   code. Record the failing assertion text in the commit body.
2. **GREEN** - smallest production change that turns that cycle's pins green.
3. **REFACTOR** - behavior-preserving cleanup only under green; no behavior
   change without a new RED.
4. Do **not** push a RED tree. A single commit may contain RED-verified tests
   plus the GREEN implementation, with local RED observations recorded in the
   commit message (same convention as PR 35 r1 / issue #30).
5. Characterization pins for *already-correct* behavior: write first, confirm
   GREEN on arrival, then **mutation-check** (temporarily break the code,
   observe RED, revert). Record "mutation-checked" in the commit body.
6. Docs-only / roadmap / plan-status / PR-reply changes have no artificial RED;
   they land under the all-green gate, ideally in the same commit as the
   behavior they describe when user-facing.

Per-cycle gate (every commit tip):

```bash
cargo fmt --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --locked --offline --lib --bins
```

No network. Do not touch `tests/s3_integration.rs` or env-gated suites.
Do not edit W25 characterization tests, walk tests, config tests, CLI, plan,
exec, or store. `Cargo.toml` / `Cargo.lock` dependency sections stay untouched
(no `globset` / `glob` / `gitignore` / `regex` crate).

This round has **no production matcher-algorithm change**. Item 2 is
characterization-only (tests). Items 1 and 3 are rustdoc. Do not "improve"
glob backtracking, dir-prefix, or validation semantics under the cover of
polish.

### W192 - R2-F2: permanent UTF-8 star characterization pins

**Goal:** Lock the UTF-8-safe backtrack advance (`chars().next().len_utf8()`)
so a future "simplify to bytes" refactor cannot regress multi-byte literals
under the ASCII-only star table.

**Where:** extend the cases table inside `ignore_set_star_segment` in
`src/ignore.rs` (same test the issue and r1 F1/F2 already own).

**Rows to add** (from the r2 review, plus one path-form echo optional):

```text
# --- UTF-8 multi-byte literals / backtrack advance (r2 F2) ---
(["café*"], "caféx", true)
(["café*"], "cafex", false)
(["*é*"], "aéb", true)
(["*é*"], "aeb", false)          # optional extra negative; keep if table stays readable
(["ä*ä"], "äää", true)
(["ä*"], "xä", false)
```

Minimum set if keeping the table tight (reviewer's list verbatim):

```text
(["café*"], "caféx", true)
(["café*"], "cafex", false)
(["*é*"], "aéb", true)
(["ä*ä"], "äää", true)
(["ä*"], "xä", false)
```

Do **not** remove any existing anchor/backtrack/happy-path rows.

**TDD protocol (characterization - already GREEN on tip):**

1. Add the rows only; no production change.
2. Run:

   ```bash
   cargo test --locked --offline --lib ignore_set_star_segment -- --exact --nocapture
   ```

   Expected: **GREEN on arrival** (all new rows pass under current
   `segment_glob_matches` / `match_after_star`).

3. **Mutation-check (required):** temporarily break UTF-8 advance in
   `match_after_star`, e.g. replace

   ```rust
   let next = seg[pos..].chars().next().map_or(1, char::len_utf8);
   from = pos + next;
   ```

   with a byte step that is wrong for multi-byte starters when a multi-byte
   literal must be re-found, **or** (simpler, reliable RED): temporarily
   make the final-literal / search path use a lossy ASCII-only view such as
   skipping non-ASCII segments (`if seg.bytes().any(|b| b > 127) { return false; }`
   at the top of `segment_glob_matches`). Observe at least one UTF-8 row RED
   (e.g. `café*`/`caféx` or `ä*ä`/`äää`). Revert the mutation.

4. Record in the commit body: "characterization: GREEN on arrival;
   mutation-checked: \<describe break\> re-fails \<row\>; reverted."

**Production change:** none.

**Gate:**

```bash
cargo fmt --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --locked --offline --lib --bins
cargo test --locked --offline --lib ignore
```

**Commit:**

#### R2-F3 - `matches` key-validity sentence

ignore as a path-safety boundary. Shape (normative intent, not mandatory

/// True when `key` (vault-relative entity key) is ignored by any pattern.
///
/// `key` should already be a vault-relative entity key accepted by
/// [`crate::entity::ensure_valid_key`]. This matcher is pure string/segment

/// components are not rejected here).

resolves cleanly at `cargo doc` time; if the link is awkward from this module,
a plain prose mention of `entity::ensure_valid_key` is enough. Do **not**
change the function body.

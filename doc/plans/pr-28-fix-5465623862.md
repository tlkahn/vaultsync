## Implementation discipline

Use strict fine-grained TDD:

1. For every behavior change, write or update the exposing test first, run it, and observe the expected RED failure before touching implementation.
2. Implement the minimum change that turns the RED test GREEN.
3. Run the focused test, then the relevant module suite, then the full gate.
4. Refactor only under GREEN, keeping behavior pinned.
5. Do not push a RED tree. A commit may contain both the RED-verified tests and the GREEN implementation, with the local RED observations recorded in the commit message.
6. For tests that pin already-correct behavior, write the test first, confirm it is GREEN on arrival, then perform a mutation check: temporarily break the behavior, observe RED, revert, and record the mutation check in the commit message.
7. Documentation-only changes do not need artificial RED tests, but user-facing docs that describe changed behavior land in the same commit as that behavior.

Per-cycle gate:

```bash
cargo fmt --check
cargo clippy --all-targets --locked -- -D warnings
cargo test --locked --lib --bins
```

Integration tests remain env-gated to CI unless explicitly requested.

## Scope decision: target fixed layout

Use this layout:

```text
{verb:<12}{key:<12}  {done}/{total}  [{8-cell bar}]  {pct:>3}% {rate} ETA {eta}
```

Concrete budgets:

- Verb labels:
  - `Uploading`
  - `Downloading`
  - `Del remote`
  - `Del local`
- Verb field: 12 columns, so the longest label (`Downloading`, 11 chars) still gets one separating space.
- Key field: 12 columns, char-boundary-safe truncation as today.
- Separators before count, bar, and percent: two spaces as today.
- Bar: 8 interior cells plus brackets, 10 columns total.
- Percent: existing `{pct:>3}%`, 4 columns at `100%`.
- Rate suffix: one space plus the existing `human_rate` text.
- ETA suffix: one space plus `ETA {eta}`.
- Rate and ETA still appear only under the existing `bytes_done > 0 && elapsed_ms > 0` rule.

Width budget for the pinned common worst case:

```text
verb field                 12
key field                  12
two spaces                  2
fraction "9999/10000"      11
two spaces                  2
8-cell bar with brackets   10
two spaces                  2
percent field               4
space + max rate           13   ("1023.9 GiB/s" is 12)
space + hour ETA           12   ("ETA 1:01:01" is 11)
total                      80
```

This covers the review's stated rate + short-ETA case with margin, and also covers a one-digit-hour `h:mm:ss` ETA at 10k-key count width. It does not introduce terminal-width probing. Terminals narrower than 80 columns and pathological values outside this envelope remain outside Option A's scope; width-aware rendering remains the possible follow-up Option B.

The new `doc/cli.md` sample should be generated from the same shape:

```text
Uploading   notes/foo.md  847/1204  [=====>--]   70% 12.4 MiB/s ETA 1:12
```

At 70%, the 8-cell body is `=====>--`: five `=` cells, one `>` head, and two `-` cells.

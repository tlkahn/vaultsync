## Refuted / corrected claims (for the record)

1. **M4 "with no signal"**: **overstated**. Pull against a no-mtime remote does emit a plan row (`Skip` / `local_newer`). Status/Push even surface `Upload` / `local_newer`. The real hole is **misleading reason + execute-time keep-local**, not a total absence of output. The revisit note should say "Pull keeps local with a Skip that looks like a deliberate local-wins, not an unknown-mtime warning" rather than "no signal".
2. **H2 "process abort" as the only outcome**: platform-dependent (OOM kill, panic, overcommit-then-fault). The defect is **trusting caller `size` for allocation before reading**; the fix is the same regardless of how the kernel reports pain. We will not probe `u64::MAX` allocation in CI.
3. **L4 as a fresh bug**: **not a regression / not an accidental hole**. P1r4-vault-value deliberately rejects leading `-` so `--vault --delete` cannot swallow `--delete` as a path. The unreachable vault name `-foo` is the documented tradeoff (`./-foo` works). Clap migration note only.
4. **No fully FALSE findings** in this round. Both highs are live; mediums are real doc/note work; lows are real with the dispositions above.

Everything else in the comment verified **true** as stated, including the claim that rounds 1-4 issues remain closed (tolerance classifier, mode-aware forces, `status --delete`, key/control-char validation, remote ingest, walker TOCTOU, single-stat, content-derived etags, reentrant `get_to` lock test).

## Method: strict fine-grained TDD

Every behavior-bearing change follows one cycle:

1. **RED** - write the named test first; run *only that test*; confirm it fails for the *right* reason (assertion/mismatch or missing API, not a harness typo).
2. **GREEN** - smallest production change that makes that test pass. No second feature, no speculative helpers.
3. **REFACTOR** - names/structure only; suite stays green. Refactors do not add behavior.

Rules of engagement:

- One logical behavior per cycle. Prefer many small cycles over one "fix dump".
- Tests name the behavior (`local_unix_backslash_filename_fails_walk`), not the ticket number.
- Characterization tests (REAL-CHAR) document existing intended behavior: write the test, confirm it **passes immediately**, treat as a lock. If it fails, the behavior was not what the review assumed - stop and re-disposition.
- Do not expand production code without a failing test that demands it (except pure wiring the next RED cannot compile without - keep that minimal and covered immediately after).
- After each slice below, run full `cargo test` before starting the next slice.
- No network. No new crates (std-only, per repo dependency policy).
- Do not implement Phase 2 S3/TOML/executor under this plan.
- Docs-only slices skip RED/GREEN but still get a verification step (`rg`, test count).
- Probe tests used for this plan's verification stay out of the tree (already removed).

### Cadence

```text
# RED
# edit: add exactly one new #[test] (or one focused assertion)
cargo test -p vaultsync -- --nocapture <exact_test_name>
# confirm FAIL for the right reason

# GREEN
# edit: minimal prod change
cargo test -p vaultsync -- --nocapture <exact_test_name>
# confirm PASS

# full suite
cargo test
# optional refactor -> cargo test
```

When a cycle touches CLI parse, prefer lib-level `parse_args` / `run_with_io` tests (no process spawn). Local walk tests use `TempDir` (already in `testutil`).

## Locked decisions for this plan

1. **`path_to_key` (H1 + L2):** build the key by iterating `rel.components()`:
   - `Component::Normal(os)` -> `os.to_str().ok_or(InvalidKey non-UTF8)?`, push segment
   - `Component::ParentDir` / `CurDir` / `Prefix` / `RootDir` -> `InvalidKey` (defense in depth; `ensure_valid_key` still runs on the joined string)
   - join segments with `/`, then `ensure_valid_key(&key)?`
   - **No** `replace('\\', "/")`. On Windows, `components()` already yields separator-free `Normal` parts, so nested `a\b.md` on disk becomes `a/b.md` correctly. On Unix, a file whose name contains `\` stays one segment and fails `ensure_valid_key`'s backslash rule (fail loud, P1r4-key-ctl consistent).
2. **Mock read (H2):** `read_exact_n(r, size: u64)` uses `Read::take` + `read_to_end` into a `Vec::new()`, then checks `buf.len() as u64 == size`. Short -> `UnexpectedEof`. No `vec![0u8; n]`. No `size as usize` cast at the allocation boundary. `put_from` keeps the existing trait contract (exactly `size` bytes; extra reader bytes ignored).
3. **Human cli.md (M3):** Phase 1 human block documents what `format_plan_human` actually emits (`delete_local` / `delete_remote` counts; action prefixes `U`/`D`/`DL`/`DR`/`S`/`*`; conflict reason token as-is; **no** size column). A one-line note marks byte sizes as Phase 2+. JSON example stays the source of truth for structured counts.
4. **None-mtime (M4):** Phase 1 classify rule unchanged (`unwrap_or(0)`). Characterization test locks Pull -> `Skip`/`local_newer` for remote `None` + local present (diff size and same size variants). Decision-log revisit note gains an explicit pull-direction bullet; Phase 2 checklist row names "Pull staleness / status visibility for None-mtime pairs".
5. **Vault root (L1):** after `fs::metadata(&self.root)?`, if `!md.is_dir()` return `Error::Other(format!("vault root is not a directory: {}", self.root.display()))`. Missing root still surfaces as IO error (existing test). File-root gets the new clear message.
6. **Recursion / `-foo` vault (L3/L4):** docs/checklist only.

## Method: strict fine-grained TDD

Every behavior-bearing change follows one cycle:

1. **RED** - write the named test first; run *only that test*; confirm it fails for the *right* reason (assertion/mismatch or missing API, not a harness typo).
2. **GREEN** - smallest production change that makes that test pass. No second feature, no speculative helpers.
3. **REFACTOR** - names/structure only; suite stays green. Refactors do not add behavior.

Rules of engagement:

- One logical behavior per cycle. Prefer many small cycles over one "fix dump".
- Tests name the behavior (`mock_etag_stable_for_same_content`), not the ticket number.
- Characterization tests (REAL-CHAR) document existing intended behavior: write the test, confirm it **passes immediately**, treat as a lock. If it fails, the behavior was not what the review assumed - stop and re-disposition.
- Do not expand production code without a failing test that demands it (except pure wiring the next RED cannot compile without - keep that minimal and covered immediately after).
- After each slice below, run full `cargo test` before starting the next slice.
- No network. No new crates (std-only, per repo dependency policy). FNV-1a is ~8 lines of `wrapping_mul`; no `const fn` tricks needed.
- Do not implement Phase 2 S3/TOML/executor under this plan.
- Docs-only slices skip RED/GREEN but still get a verification step (`rg`, test count).
- `debug_assert!` additions are contract assertions, not behavior: they land with a comment and the existing suite as the green bar, no dedicated panic test.

### Cadence

```text
# RED
# edit: add exactly one new #[test] (or one focused assertion)
cargo test -p vaultsync -- --nocapture <exact_test_name>
# confirm FAIL for the right reason

# GREEN
# edit: minimal prod change
cargo test -p vaultsync -- --nocapture <exact_test_name>
# confirm PASS

# full suite
cargo test
# optional refactor -> cargo test
```

When a cycle touches CLI parse, prefer lib-level `parse_args` / `run_with_io` tests (no process spawn).

## Locked decisions for this plan

1. **Etag (A1):** mock etag = lowercase hex FNV-1a-64 over stored bytes (`format!("{:016x}", h)`). Content-derived, comparable across store instances and processes; same content re-put yields the same etag; `mtime_ms` does not feed the hash (matches S3 small-object MD5 semantics: content only). Trait/entity docs still call etag an opaque token *for planner purposes* (planner never compares etags in Phase 1), but the mock's are now safe to compare in fixtures.
2. **Key rules (B1):** `ensure_valid_key` additionally rejects (a) any control character anywhere in the key (`char::is_control`, covers NUL, CR, LF, TAB, DEL), and (b) any segment that is entirely whitespace. `...` and segments with leading/trailing spaces remain valid: they occur in real vaults, round-trip through S3 cleanly, and the output-integrity hole is closed by (a). Local emit (`path_to_key`) and mock `put_from` inherit; a local file whose name violates the rules now fails the walk **loud** (fail closed) instead of emitting a corrupt key.
3. **Remote ingest (B1):** `build_plan` validates every key returned by `store.list("")` with `ensure_valid_key` before planning; invalid keys are `Error::InvalidKey`, not planned actions. `plan()` itself stays pure (fixtures may feed it anything).
4. **`--vault` (B2):** value must be non-empty and must not start with `-` (standard hygiene; a path that genuinely starts with `-` is spelled `./-foo`). Repeated `--vault` is a parse error (fail loud over silent last-wins).
5. **Walker (A3):** one `fs::metadata` per file feeds both `size` and `mtime_ms`. `NotFound` anywhere after `read_dir` (entry vanished, dir vanished before recursion) skips that entry; all other errors (permission, etc.) stay fatal. No warning channel in Phase 1 (the walker returns entities only); the skip is silent-by-design and documented.
6. **Pre-epoch mtime (A4):** `system_time_to_ms` saturates pre-epoch times to `Some(0)`. `None` again means only "FS could not tell us". Note added to the `P1r-mtime-none` revisit row.
7. **Folder contract (A-low-1/B3):** `list` synthesizes folder *views*; folder keys are not objects. `head`/`get_to`/`delete` accept object keys only; callers must branch on `Entity::is_folder()` (or filter) before object ops. Phase 2 S3 must match (CommonPrefixes are not `HeadObject` targets).
8. **Folder mtime asymmetry (A-low-2):** local folders keep real mtimes (`Some`); mock/remote synthesized folders use `None`. Locked as intentional; Phase 2 must not compare folder mtimes across sides.
9. **Symlinks (B5):** all symlinks (files and directories) are skipped, silently, by default. Phase 2 owns a follow/warn policy.

## Phase 2 checklist rows: strengthen + add (roadmap.md)

- Strengthen existing **Remote key ingest validation (R2.2)** row: note that control chars + ws-only segments are now rejected at `ensure_valid_key` and `build_plan` validates `list` output (P1r4-remote-ingest); remaining executor work: validate `head` responses too, and route *all* local path construction through a single `key_to_local_path(vault, key) -> Result<PathBuf>` that validates before joining.

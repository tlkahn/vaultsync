## Method: strict fine-grained TDD

Every behavior-bearing change follows one cycle:

1. **RED** - write the named test first; run *only that test*; confirm it fails for the *right* reason (assertion/mismatch, not a harness typo).
2. **GREEN** - smallest production change that makes that test pass. No second feature, no speculative helpers.
3. **REFACTOR** - names/structure only; suite stays green. Refactors do not add behavior.

Rules of engagement:

- One logical behavior per cycle. Prefer many small cycles over one "fix dump".
- Tests name the behavior (`plan_pull_force_local_conflict_skips`), not the ticket number.
- Do not expand production code without a failing test that demands it (except pure wiring the next RED cannot compile without - keep that minimal and covered immediately after).
- After each slice below, run full `cargo test` before starting the next slice.
- No network. No new crates (std-only). Confirm with the user before any dependency.
- Do not implement Phase 2 S3/TOML/executor under this plan.
- Docs-only slices skip RED/GREEN but still get a verification step (`rg`, test count).

### Cadence

```text
# RED
# edit: add exactly one new #[test] (or one focused assertion)
cargo test -p vaultsync -- --nocapture <exact_test_name>
# confirm FAIL for the right reason

# GREEN
# edit: minimal prod change
cargo test -p vaultsync -- --nocapture <exact_test_name>
# confirm PASS

# full suite
cargo test
# optional refactor -> cargo test
```

When a cycle touches CLI parse, prefer lib-level `parse_args` / `run_with_io` tests (no process spawn).

## Locked force x mode semantics (R3.1)

For `Delta::Conflict` only (forces never touch other deltas):

| force_local | force_remote | Status | Push | Pull |
| ----------- | ------------ | ------ | ---- | ---- |
| false | false | Conflict | Conflict | Conflict |
| true | true | Conflict (cancel) | Conflict | Conflict |
| true | false | Upload `force_local` | Upload `force_local` | **Skip** `force_local` (keep local) |
| false | true | Download `force_remote` | **Skip** `force_remote` (keep remote) | Download `force_remote` |

Rationale:

- Push may only plan Upload / DeleteRemote / Skip / Conflict.
- Pull may only plan Download / DeleteLocal / Skip / Conflict.
- Status remains a bidirectional *report* of the winning side's transfer direction.
- Both forces set: keep existing cancel -> Conflict `conflict_mtime_size` (P1r-both-forces).

Suggested production shape (illustrative; write tests first):

```rust
Delta::Conflict => match (opts.force_local, opts.force_remote) {
    (true, true) | (false, false) => (Conflict, reason::CONFLICT_MTIME_SIZE),
    (true, false) => match mode {
        Mode::Push | Mode::Status => (Upload, reason::FORCE_LOCAL),
        Mode::Pull => (Skip, reason::FORCE_LOCAL),
    },
    (false, true) => match mode {
        Mode::Pull | Mode::Status => (Download, reason::FORCE_REMOTE),
        Mode::Push => (Skip, reason::FORCE_REMOTE),
    },
},
```

Also update:

- `PlanOpts` doc comments (`force_local` / `force_remote`) away from "always upload/download".
- `phase-1.md` Conflict matrix row to the table above.
- `roadmap.md` decision-log row `P1r3-force-mode`.

### Slice D - `get_to` drops lock before write (R2.4)

#### D1. Behavioral lock: get still returns bytes + entity

Existing `mock_put_get_roundtrip` already covers correctness. Add a focused test only if we can observe lock scope without sleeps/threads flaking.

**Preferred RED (optional but good):**

| Test | Asserts |
| ---- | ------- |
| `mock_get_to_does_not_require_reentrant_store` | Custom `Write` that calls `store.head(key)` (or `list`) from inside `write`; must succeed after the fix; today deadlocks under the same mutex |

```rust
struct ReentrantWrite<'a> {
    store: &'a MemoryStore,
    key: String,
    buf: Vec<u8>,
}
impl Write for ReentrantWrite<'_> {
    fn write(&mut self, data: &[u8]) -> io::Result<usize> {
        let _ = self.store.head(&self.key); // would deadlock if lock held
        self.buf.extend_from_slice(data);
        Ok(data.len())
    }
    fn flush(&mut self) -> io::Result<()> { Ok(()) }
}
```

If a re-entrant test is too awkward on the first try: skip RED and treat as refactor-with-coverage from roundtrip; still run full suite.

**GREEN**

```rust
fn get_to(&self, key: &str, w: &mut dyn Write) -> Result<Entity, Error> {
    let (bytes, entity) = {
        let guard = self.objects.lock().unwrap();
        let obj = guard.get(key).ok_or_else(|| Error::NotFound(key.to_string()))?;
        (obj.bytes.clone(), self.entity_for(key, obj))
    }; // guard dropped
    w.write_all(&bytes)?;
    Ok(entity)
}
```

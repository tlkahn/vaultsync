### W52 - De-quadratic `path_collision_keys` (B-M2)

**Fix:** exploit the sorted, dedup'd input. For each non-folder key `k`, descendants `k/...` are contiguous: binary-search the first index `>= "{k}/"` and scan forward while `starts_with("{k}/")`. For each folder key, binary-search for the exact base instead of `keys.contains`. Overall O(n log n).

- RED:
  - `path_collision_keys_matches_naive_reference`: test-local naive O(n^2) reference (the current algorithm, copied into the test module) compared against the production function over several randomized key sets (seeded, deterministic), including `K` vs `K/x`, `K/` folder markers, case variants, and trailing-slash edges. RED because the production function is currently private to `plan/mod.rs` - expose it to the crate (`pub(crate)`) as part of this item.
  - `path_collision_keys_catches_collision_at_scale`: 100k synthetic `dirNNNNN/fileNNNNN.md` keys plus one planted `zz/collide` + `zz/collide/x.md` pair; assert the pair (and only the expected keys) is reported. Guards against a windowed-scan boundary bug at scale. (Runtime assertion, not a benchmark - debug-build-safe.)
- GREEN: rewrite `path_collision_keys` with `partition_point` binary searches + windowed scan. Existing collision tests (4a locks) must stay green unchanged - they are the equivalence net together with the naive-reference test.
- Refactor: keep the function signature and `BTreeSet<String>` return (callers untouched).

snapshot (size + mtime + etag all from the same HeadObject), aligning the
W106 `CappedWriter` cap and the pass-3 size re-check with the mtime identity

`enrich_corrects_stale_listing_size_with_head_size`. Build from
`degraded_listing()`, then corrupt one file entity's `size` (e.g. `9_999`,
the mock's true size is 1) before enriching. Assert the enriched entity's
`size` equals `store.head(key).size`. RED today: size stays `9_999`.

**GREEN**: add `e.size = h.size;` in `enrich_with_head_mtimes`. Rewrite the
helper rustdoc contract paragraph: drops "only `mtime_ms` and `etag` are
overridden (`size` stays as listed - ... `plan()` tolerates either value)";
states size/mtime/etag all come from head, names the CappedWriter /
head-before-delete alignment, and scopes the residual race to the
enrich-head -> get/delete-head window. Also flip the s3.rs module-doc

describes this exact behavior).

### W117 - bounded retry on transient head errors inside the enrich loop (R2-3, adopted per R16-scope-retry)

Behavior change: `Error::Unavailable` and `Error::Timeout` from a head are
retried with a small fixed backoff before failing closed; all other errors
(NotFound drop, Unauthorized, Other) keep their single-attempt semantics.
This is a stopgap; full backoff/jitter/pool remains Phase 3 item 3 (W123
makes that coupling explicit).

Policy constants (private to src/store/mod.rs): `HEAD_MAX_ATTEMPTS = 3`
(1 initial + 2 retries), backoff `[100ms, 300ms]` via
`std::thread::sleep` (helper is sync; no async outside store::s3). Worst
added latency per key is 400ms, only on the failing path.

**RED** (src/store/mod.rs tests; a counter-equipped flaky stub, in-memory,
no real sleeping concern beyond the 400ms worst case):

1. `enrich_retries_transient_head_errors` - stub fails the first 2 heads
   with `Unavailable`, then answers; assert enrich succeeds and the stub saw
   exactly 3 head calls. Also parameterize one run with `Timeout` for the
   first failure (both variants retried). RED today: the first `Unavailable`
   fails the whole listing.
2. `enrich_retry_is_bounded_and_fail_closed` - existing `HeadFailStore`
   (always `Unavailable`) gains a call counter; assert `Err` after exactly
   `HEAD_MAX_ATTEMPTS` calls (fail-closed preserved, bound pinned).
3. `enrich_does_not_retry_nontransient_errors` - stub fails with
   `Unauthorized`; assert `Err` after exactly 1 head call.

**GREEN**: private `head_with_retry` used by the enrich loop; rustdoc notes
the stopgap and that the Phase 3 pool owns full retry/backoff/jitter.

**Refactor**: keep the retry helper private; no new API surface (R1-L4
spirit).

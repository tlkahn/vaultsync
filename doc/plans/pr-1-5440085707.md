## Refuted / corrected claims (for the record)

1. **No FALSE findings in this round.** All eight items verified true as stated.
2. **M1 is a skip-policy hole, not a validation-policy regression.** The fix must not make invalid-named *files/dirs* skippable - P1r4-key-ctl / P1r5-backslash-key fail-loud stays exactly as locked. The reorder changes behavior only for nodes that are never emitted (not dir, not file, not symlink). Existing walker tests are the guardrail; they must pass unmodified.
3. **L1 severity is consistency, not data loss.** `push --delete --delete` behaves identically to `push --delete`; nothing is silently *dropped* (unlike the round-4 `--vault --delete` swallow). The fix is justified by the parser's own locked rule (P1r4-vault-value: fail loud over silent acceptance), not by a user-facing hazard.
4. **L2 rule choice is "always append USAGE", not "never".** `unknown command` / `unknown flag` / trailing-token branches already append; uniformity means extending the two short branches (and L1's new message), not trimming the long ones. Bare `vaultsync` / `help` / `--help` output (USAGE to **stdout**, exit 0) is display, not an error, and is untouched.
5. **N1 correction:** the review says the `CurDir` arm "is unreachable" - slightly overstated. Interior `.` is normalized away, but a **leading** `CurDir` *is* yielded by `components()` (e.g. `Path::new("./a.md")`). The arm is dead for walker-produced relative paths (strip_prefix output never starts with `.`), which is what the comment must now say. No code change.
6. **M2 stays Phase 2.** No Phase 1 walker change for the symlink-swap race: closing it in the walker alone (re-`file_type` before recursion) narrows but cannot close the executor-era window, and Phase 1 has no executor. Checklist row only; do not half-fix.

## Method: strict fine-grained TDD

Every behavior-bearing change follows one cycle:

1. **RED** - write the named test first; run *only that test*; confirm it fails for the *right* reason (assertion/mismatch or missing API, not a harness typo).
2. **GREEN** - smallest production change that makes that test pass. No second feature, no speculative helpers.
3. **REFACTOR** - names/structure only; suite stays green. Refactors do not add behavior.

Rules of engagement:

- One logical behavior per cycle. Prefer many small cycles over one "fix dump".
- Tests name the behavior (`local_skips_special_file_with_backslash_name`), not the ticket number.
- Characterization tests (REAL-CHAR) document existing intended behavior: write the test, confirm it **passes immediately**, treat as a lock. If it fails, the behavior was not what the review assumed - stop and re-disposition.
- Do not expand production code without a failing test that demands it (except pure wiring the next RED cannot compile without - keep that minimal and covered immediately after).
- After each slice below, run full `cargo test` before starting the next slice.
- No network. No new crates (std-only, per repo dependency policy).
- Do not implement Phase 2 S3/TOML/executor under this plan.
- Docs-only slices skip RED/GREEN but still get a verification step (`rg`, test count).
- Probe tests used for this plan's verification stay out of the tree (already removed).

### Cadence

```text
# RED
# edit: add exactly one new #[test] (or one focused assertion)
cargo test -p vaultsync -- --nocapture <exact_test_name>
# confirm FAIL for the right reason

# GREEN
# edit: minimal prod change
cargo test -p vaultsync -- --nocapture <exact_test_name>
# confirm PASS

# full suite
cargo test
# optional refactor -> cargo test
```

When a cycle touches CLI parse, prefer lib-level tests (no process spawn). Local walk tests use `TempDir` (already in `testutil`). FIFO fixtures use `std::os::unix::fs::FileTypeExt` / `mkfifo` via `std::process::Command` **only if** no std API exists - check first: std has no `mkfifo`, so use `libc`-free shell-out (`Command::new("mkfifo")`) under `#[cfg(unix)]`, matching the existing pattern of unix-gated tests without adding crates. Non-UTF8 names use `std::os::unix::ffi::OsStrExt` as established.

## Implementation notes (as landed, commit for this round)

- **Slice A - A3 (non-UTF8 FIFO) dropped, not shipped.** The premise "write the test, confirm it passes immediately" could not be met: macOS rejects *any* invalid-UTF-8 filename at the syscall layer (`mkfifo` and `os.mkfifo` both return EILSEQ `[Errno 92] Illegal byte sequence`), so a non-UTF8-named FIFO (indeed any non-UTF8-named node) is **uncreatable** on this platform. This mirrors the existing suite, where non-UTF8 is covered only via the pure `path_to_key` function (`local_path_to_key_rejects_non_utf8_component`), never on disk. The mechanism A3 would have proven - special files never reach `path_to_key` - is already locked by A1's backslash FIFO test, which drives the identical code path (the reorder simply does not invoke `path_to_key` for non-emittable nodes). Backslash is valid UTF-8, so its FIFO fixture is creatable and is the correct on-disk lock.
- **Slice C - the table-driven test found a third non-compliant branch** beyond the plan's "two": `--delete is only valid for push/pull, not status` also lacked USAGE. Fixed alongside the planned `repeated --vault` and `--vault requires a path argument` per the locked always-append rule (P1r7-parse-usage).
- **Final test count: 138** (135 baseline + A1 + B1 + C1), not the plan's estimated 140, because A3 was dropped.

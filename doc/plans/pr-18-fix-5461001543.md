## Work items

### W125 - F1: least-privilege `permissions:` on the CI workflow

Add at workflow level in `.github/workflows/ci.yml` (top-level key, between `concurrency:` and `env:`):

```yaml
permissions:
  contents: read
```

All four jobs only read the checkout; `contents: read` covers `actions/checkout` and `rust-cache` (cache uses the actions cache API, not repo contents write). No job needs `pull_requests: write` (no commenting) or `checks: write`.

Gate + push. **On-PR verification (part of the acceptance test):** all five checks rerun green with the restricted token - this proves no job silently relied on default permissions.

### W126 - F2: MSRV coupling comments (three-way, per R18-f2)

Comments only; no behavior change. Make the coupling explicit at each of the three sites:

1. `Cargo.toml` (above `rust-version = "1.95"`): append a line to the existing MSRV comment block - "Coupling: `.github/workflows/ci.yml` (`RUSTUP_TOOLCHAIN` + the `msrv` job name) must be updated in the same commit as any bump of this value." (Lands in W127's rewrite of the same comment block - one commit touches Cargo.toml once.)
2. `ci.yml` msrv job, on the `RUSTUP_TOOLCHAIN: 1.95.0` line: extend the existing inline comment to "env beats rust-toolchain.toml; the declared MSRV floor - must match `rust-version` in Cargo.toml".
3. `ci.yml` msrv job, above `name: msrv (1.95)`: comment that the job name hardcodes the floor for check-list readability and must be renamed in the same commit as a `rust-version` bump.

### W127 - F4: Cargo.toml MSRV comment rewrite

Fold in the W126 coupling line so Cargo.toml is touched exactly once. Pure comment change - gate and commit.

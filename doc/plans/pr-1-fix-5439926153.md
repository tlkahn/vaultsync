## Method: strict fine-grained TDD

Every behavior-bearing change follows one cycle:

1. **RED** - write the named test first; run *only that test*; confirm it fails for the *right* reason (assertion/mismatch or missing API, not a harness typo).
2. **GREEN** - smallest production change that makes that test pass. No second feature, no speculative helpers.
3. **REFACTOR** - names/structure only; suite stays green. Refactors do not add behavior.

Rules of engagement:

- One logical behavior per cycle. Prefer many small cycles over one "fix dump".
- Tests name the behavior (`cli_args_reject_non_utf8`), not the ticket number.
- Characterization tests (REAL-CHAR) document existing intended behavior: write the test, confirm it **passes immediately**, treat as a lock. If it fails, the behavior was not what the review assumed - stop and re-disposition.
- Do not expand production code without a failing test that demands it (except pure wiring the next RED cannot compile without - keep that minimal and covered immediately after).
- After each slice below, run full `cargo test` before starting the next slice.
- No network. No new crates (std-only, per repo dependency policy).
- Do not implement Phase 2 S3/TOML/executor under this plan.
- Docs-only slices skip RED/GREEN but still get a verification step (`rg`, test count).
- Probe tests used for this plan's verification stay out of the tree (already removed).

### Cadence

```text
# RED
# edit: add exactly one new #[test] (or one focused assertion)
cargo test -p vaultsync -- --nocapture <exact_test_name>
# confirm FAIL for the right reason

# GREEN
# edit: minimal prod change
cargo test -p vaultsync -- --nocapture <exact_test_name>
# confirm PASS

# full suite
cargo test
# optional refactor -> cargo test
```

When a cycle touches CLI parse, prefer lib-level tests (no process spawn). Local walk tests use `TempDir` (already in `testutil`). Unix-only argv fixtures use `std::os::unix::ffi::OsStrExt` under `#[cfg(unix)]`, matching the existing pattern.

## Locked decisions for this plan

1. **Argv conversion (M1):**
   - `run_from_env` collects `std::env::args_os()` into `Vec<OsString>`.
   - New private helper in `src/cli.rs`:

     ```rust
     fn os_args_to_strings(args: Vec<OsString>) -> Result<Vec<String>, String> {
         args.into_iter()
             .map(|a| a.into_string().map_err(|os| {
                 format!("argument is not valid UTF-8: {os:?}")
             }))
             .collect()
     }
     ```

   - On `Err(msg)`, `run_from_env` prints `error: {msg}` to stderr and returns 1 (same exit channel as parse errors). On `Ok`, behavior is identical to today.
   - Phase 1 stays fail-closed: a non-UTF8 vault *root* remains unreachable from the CLI. Decision-log row records the possible Phase 2+ refinement (OsString-aware `--vault` value -> `PathBuf` directly) without committing to it.

Decision-log row `P1r6-mtime-zero` amends the `P1r-mtime-none` / `P1r5-mtime-pull` revisit chain.
3. **Stub exit codes (L2):** no code change. Characterization test `run_push_stub_conflict_exit_0_placeholder` asserts exit 0 with a conflict present and names the Phase 2 exit-code lock in its comment. Phase 2 checklist reaffirmed verbatim.
4. **Symlinked root (L4):** behavior unchanged. `local` module header omissions list gains a bullet: a symlinked vault *root* is followed (`fs::metadata` on the root resolves it); the skip-all-symlinks rule applies to entries below the root. `#[cfg(unix)]` characterization test locks it.

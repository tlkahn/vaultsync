2. **Refute** false positives and overstated framings in writing so they do not re-enter the queue.

**Exit criteria for this plan's implementation:**

- `Cargo.toml` has no `registry = "rsproxy-sparse"` keys; `Cargo.lock` re-resolved to the canonical crates-io index; a clean-`CARGO_HOME` resolution check passes.

- Case-variant file-vs-folder collisions (`Notes` vs `notes/`) are flagged Conflict.

- `dt_millis` saturates pre-epoch like the local side; 5xx/429 map to `Error::Unavailable`.
- Delete semantics are one contract across backends (executor treats already-gone as success).
- Pull re-verifies destination freshness before overwrite (symmetric to R3.3).
- Clippy clean (lib + tests; spike example fixed or gated); docs updated.
- `cargo test` green; `cargo fmt --check` clean.

## TDD ground rules (apply to every work item)

1. **RED first.** Write the failing test (or the failing verification step) that exposes/replicates the finding. Run it; confirm it fails for the expected reason; paste/keep the failure output in the commit message or PR note when non-obvious.
2. **GREEN minimal.** Smallest change that flips the test. No drive-by edits.
3. **REFACTOR** with tests green (naming, duplication, comments).
4. After each item: `cargo test --offline`, `cargo fmt --check`, `cargo clippy` (lib) must be clean; one commit per work item.
5. Existing characterization tests that lock the *old* behavior (e.g. `s3_error_mapping` asserting 500 -> `Other`) are amended in the same commit with a citation of this plan + review comment IDs, matching the project's amended-test convention.
6. Signature changes (`execute_plan`, `open_verified`, `run_with_io`) update all call sites and their tests in the GREEN step; the refactor step re-checks ergonomics.

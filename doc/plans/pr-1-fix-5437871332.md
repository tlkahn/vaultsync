## Method: strict fine-grained TDD

Every behavior-bearing change follows one cycle:

1. **RED** - write the named test first; run *only that test*; confirm it fails for the *right* reason (assertion/mismatch, not a harness typo).
2. **GREEN** - smallest production change that makes that test pass. No second feature, no speculative helpers.
3. **REFACTOR** - names/structure only; suite stays green. Refactors do not add behavior.

Rules of engagement:

- One logical behavior per cycle. Prefer many small cycles over one "fix dump".
- Tests name the behavior (`plan_conflict_mtime_within_tol_diff_size`), not the ticket number.
- Do not expand production code without a failing test that demands it (except pure wiring the next RED cannot compile without - keep that minimal and covered immediately after).
- After each slice below, run full `cargo test` before starting the next slice.
- No network. No new crates (std-only). Confirm with the user before any dependency.
- Do not "fix forward" into Phase 2 executor/S3/TOML work under this plan.

### Cadence

```text
# RED
# edit: add exactly one new #[test] (or one focused assertion)
cargo test -p vaultsync -- --nocapture <exact_test_name>
# confirm FAIL for the right reason

# GREEN
# edit: minimal prod change
cargo test -p vaultsync -- --nocapture <exact_test_name>
# confirm PASS

# full suite
cargo test
# optional refactor -> cargo test
```

When a cycle touches CLI parse, prefer lib-level `parse_args` / `run_with_io` tests (no process spawn).

### Slice C - Key validation choke points (high, minimal)

**Lock (this PR):**

- Extend `ensure_valid_key` to reject:
  - any path segment that is `.` or `..`
  - empty segments (split on `/` yields `""`), except a single trailing empty from a folder key's final `/`
- Call `ensure_valid_key` from:
  1. `MemoryStore::put_from` before insert
  2. `LocalFs` walk after key string is built (file and folder), before push to `out`
- Do **not** yet call from `plan()` (planner stays pure over pre-validated entities; bad fixtures in unit tests remain authoring errors).
- Do **not** build a full Unicode/Windows path library.

Folder keys end with `/`. Validation rule for segments:

```text
key "notes/hello.md" -> segments ["notes", "hello.md"]
key "notes/"         -> segments ["notes"]            # drop trailing empty from final /
key "notes//x.md"    -> segments ["notes", "", "x.md"] -> reject empty
key "../x.md"        -> segments ["..", "x.md"]       -> reject
key "foo/../x.md"    -> reject
key "foo/./x.md"     -> reject
key ".hidden"        -> segments [".hidden"]          # OK (name is not segment "." )
key "foo/."          -> reject
key "foo/.."         -> reject
```

Leading `/` and `\` already rejected.
